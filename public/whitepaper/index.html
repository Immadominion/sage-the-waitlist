Section 1

Abstract

Aura is an autonomous capital execution platform for Solana. It combines a proprietary dataset of decoded Meteora DLMM transactions, a machine learning model trained on historical LP position outcomes, and a mobile execution surface where users deploy capital under their own control.

The system addresses a specific inefficiency: profitable liquidity provision strategies exist on Meteora DLMM but require constant monitoring, deep expertise, and custom tooling. Aura automates the decision-making process by training on real position outcomes extracted from Solana's block archive, then executing on behalf of users who retain full custody of their funds.

Section 2

Problem

Meteora's Dynamic Liquidity Market Maker (DLMM) concentrates swap fees to liquidity providers in the active price bin. When positioned correctly, LPs earn the entire fee from swaps in their bin — not a proportional share. This creates outsized returns for informed LPs and losses for uninformed ones.

Reference signal: A single automated LP bot (FreesolGames) achieved a 77% win rate across 12,635 real positions, generating consistent monthly returns. The strategy works — but only as a script on a server, not as a product.

The current landscape has three gaps:

  1. No historical data — Existing tools operate on live Meteora API data (current state). No one has decoded historical LP outcomes at scale for training.
  2. No trained models — Competitors wrap LLMs around current market data and call it "AI." No trained prediction model exists for LP entry quality.
  3. No execution product — Profitable strategies exist as terminal scripts and bots. No designed product turns intelligence into autonomous execution for non-technical users.
Section 3

Solution

Aura operates at three layers — data, intelligence, and execution — each of which is independently valuable and collectively forms a full-stack autonomous trading platform.

Three Modes of Control

The mobile app exposes three cognitive modes that match how users relate to their capital:

Mode Action Description
Execute Instant swap Convert assets immediately via Jupiter Ultra
Automate Rule-based bots User defines triggers and guardrails; system executes when conditions are met
Delegate ML-managed LP User commits capital; Aura's model decides when to enter/exit positions

Non-custodial throughout. Users connect via Solana Mobile Wallet Adapter (MWA) and sign transactions with their own wallet. Aura never holds private keys.

Section 4

Data Pipeline

The data layer is the core competitive advantage. It consists of a distributed extraction pipeline that decodes historical Meteora DLMM transactions from Solana's block archive (Old Faithful — 244 TB, epochs 544–950).

Pipeline Architecture

Old Faithful Geyser → Rust Filter Plugin → Python Decoder → Parquet → S3
  (raw blocks)        (DLMM txs only)     (24 event types)  (structured)

Event Types (24)

The decoder extracts and structures the following event types from DLMM program instructions:

Category Events
Position lifecycle PositionCreate, PositionClose, AddLiquidity, RemoveLiquidity, Rebalancing
Fees ClaimFee, ClaimFee2, CompositionFee, FeeParameterUpdate, DynamicFeeParameterUpdate
Market Swap, GoToABin, LbPairCreate
Rewards ClaimReward, ClaimReward2, FundReward, InitializeReward, UpdateRewardDuration, UpdateRewardFunder, WithdrawIneligibleReward
Position mgmt UpdatePositionOperator, UpdatePositionLockReleasePoint, IncreasePositionLength, DecreasePositionLength
Oracle IncreaseObservation

Lifecycle Reconstruction

By chaining these events per position address, we reconstruct complete LP lifecycles: 

PositionCreate → AddLiquidity → [Swaps in bins] → ClaimFee → RemoveLiquidity → PositionClose

For each lifecycle, we compute: total fees earned, impermanent loss from price movement, hold duration, market conditions at entry, and whether the position was net profitable. This labeled dataset is what the model trains on.

Section 5

Prediction Model

A single XGBoost model trained on reconstructed position lifecycles. The model answers one question: is this a good time to enter this pool?

Features

Feature Source
Volume (30m, 1h, 2h, 4h, 24h) Aggregated from Swap events
Fees (30m, 1h, 24h) Aggregated from ClaimFee + CompositionFee events
Fee efficiency (1h) Computed: fees / volume ratio
Liquidity Current pool TVL from Meteora API
APR Annualized fee rate from Meteora API
Volume-to-liquidity ratio Computed: activity relative to capital deployed

Current Performance

Metric Value
Model XGBoost, 100 estimators, max_depth=4
Training data 1,600 samples (Dune Analytics)
AUC 0.94
Target retraining 100K+ Old Faithful lifecycles
Inference <1ms per prediction

The current model is promising but thin. Retraining on 100K+ reconstructed lifecycles from the Old Faithful pipeline is the critical path to statistical confidence.

What the Data Cannot Train

The historical DLMM dataset captures activity within Meteora only. It cannot train general market regime detection (which requires external data like SOL price history, cross-DEX volumes, or funding rates) or cross-protocol analytics.

Section 6

Economics

The question: can an ML-guided LP bot generate positive returns after accounting for impermanent loss, transaction costs, and model error?

Expected Value Per Trade

Meteora DLMM concentrates 100% of swap fees to LPs in the active bin. A position in the right bin at the right time earns outsized returns. A position in the wrong bin gets IL with no fees.

Metric Value
Average profitable position gain +5% (fees over position lifetime)
Average unprofitable position loss -8% (IL exceeds fees)
Win rate with model (projected) 80%
Expected value per trade 0.80 × 5% − 0.20 × 8% = +2.4%

Monthly Projection

At 1 SOL per trade, 3–5 trades/day:

  • Daily: ~0.072 SOL
  • Monthly: ~2.2 SOL per 1 SOL deployed
  • At 5 SOL across concurrent positions: ~11 SOL/month

Consistent with FreesolGames reference data (~40 SOL/month at higher capital deployment).

Risk Factors

  1. Priority fees — Negligible at current volumes (<0.05 SOL/month at 5 trades/day)
  2. Fee dilution — More bots targeting the same pools reduces per-LP earnings
  3. Model drift — Market conditions change; weekly retraining mitigates this
  4. Token risk — High-fee pools are often memecoins with rug probability
  5. Without the model — Random entry yields ~45% win rate → expected value goes negative (−2.15% per trade)

Revenue Model

Stream Mechanism

Pro subscription $9.99/mo — unlimited bots, advanced analytics
Swap fee 0.15% integrator fee on Jupiter Ultra swaps
Data API Tiered subscription for historical DLMM data access

Section 8

Security

Non-Custodial Design

Users connect via Solana Mobile Wallet Adapter. Transaction signing happens on-device. Aura's backend never has access to user private keys.

Bot Wallet Security

For Delegate mode, per-bot keypairs are encrypted at rest with AES-256-GCM. Decryption happens in-memory during execution only. Withdrawals are whitelisted to the user's verified wallet address only.

Safety Controls

  • CircuitBreaker — Rate limits on trade frequency and exposure per bot
  • EmergencyStop — Automatic halt on consecutive losses or drawdown threshold
  • Kill switch — User can pause all operations at any time via the app
  • Position limits — Maximum concurrent positions and per-position size caps
